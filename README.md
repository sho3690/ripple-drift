# RippleDrift

決算の「良い驚き」と、取引先からの「追い風」を組み合わせて、**60営業日以内の値上がり（スイングロング）を狙いやすい日本株**を探すローカル・アプリです。ブラウザで開くと、候補銘柄が「3つのリング」で表示されます。

> 投資助言ではありません。学術研究で報告された統計的な傾向を、過去データで機械的に再現したものです。

## 公開版（GitHub Pages）

https://sho3690.github.io/ripple-drift/

GitHub Actions が平日の朝 7:30 ごろ（JST）に前営業日の終値で計算し直して公開します。公開版はサーバーが無いため、「データを更新」ボタンとテキスト登録フォームは使えません。テキストは `data/transcripts/` にファイルを置いて push してください（次回の自動更新で反映）。手動で今すぐ更新したいときは、GitHub の Actions タブから「Build and deploy to GitHub Pages」を Run workflow するか、ローカル版を使います。

EDINET 連携を公開版でも使うには、リポジトリの Secrets に `EDINET_FSA_KEY` を登録します。

```bash
gh secret set EDINET_FSA_KEY -R sho3690/ripple-drift < ~/cre-scout/tools/edinet_key_fsa.txt
```

## はじめかた（1コマンド・ローカル版）

```bash
cd ~/ripple-drift
./run.sh
```

初回は Python の仮想環境作成・ライブラリ導入・市場データ取得で 2〜3 分かかります。終わるとブラウザが自動で開きます（http://127.0.0.1:8765）。止めるときはターミナルで `Ctrl+C`。

- 最新データで計算し直す: 画面右上の「データを更新」ボタン、または `./run.sh --refresh`
- サーバを使わずに計算だけ: `.venv/bin/python -m app.pipeline`
- テスト: `.venv/bin/python -m pytest -q`

## 画面の構成（上から順に）

1. **今やること** — 状態に合わせて「いつ・何をするか」を5ステップで表示します。更新済みか、候補が何件か、テキストが未登録か、今日入るべきか、見直し日はいつか、が一目で分かります。丸いボタンは更新・候補・テキスト登録・根拠へのショートカットです。
2. **ルール** — 3つのシグナルの意味と、選ぶ／入る／持つ／出る／やらない の売買ルール。
3. **きょうの候補** — 候補数と、過去データでの平均ドリフト・勝率。
4. **候補銘柄** — 上位5%。行を押すと「入るなら／見直し日／次の決算」の行動プラン、理由、注意点、グラフ、テキスト登録フォームが開きます。
5. **過去データで確かめる** — ルールの根拠となる検証結果。
6. **サプライチェーン図**、**データの状態**。

## 対象銘柄（ユニバース）

既定では次の2つを合わせた約1,400銘柄を審査します。

| 区分 | 内容 | 出どころ |
|---|---|---|
| 同梱リスト | トヨタ系サプライヤー、Apple/TSMC 向け部品、任天堂サプライヤーなど、取引先の関係が分かる約120銘柄 | `app/universe.py`（出典区分つき） |
| スクリーナー | 東証上場で時価総額 300 億円以上、売買代金 1 億円/日以上の全銘柄 | Yahoo Finance のスクリーナー（7日キャッシュ） |

日本語の社名は EDINET の提出者リストから取ります（キーが無い場合は英語名）。中小型株も含むため、値動きの大きい銘柄が候補に入りやすくなります。各銘柄には「値動き 大／中／小」（年率ボラティリティの三分位）が付き、候補一覧のチェックボックスで「値動きの小さい銘柄を除く」こともできます。

環境変数で調整できます: `RIPPLE_MCAP_MIN`（時価総額の下限、既定 3e10）、`RIPPLE_MIN_TURNOVER`（売買代金の下限、既定 1e8）、`RIPPLE_UNIVERSE_MAX`（上限件数、既定 1500）、`RIPPLE_UNIVERSE=curated`（同梱リストのみ）。初回は決算データの取得に 5〜10 分かかります。

## 「経営陣の自信」のデータ源（自動取得）

| 源 | 内容 | 取得のしかた |
|---|---|---|
| TDnet（東証 適時開示） | 決算短信の「経営成績等の概況」「今後の見通し」（四半期ごと） | 公開されている直近約40日分を毎回取り込み、`data/transcripts/` に蓄積。公開版では GitHub Actions がリポジトリに自動コミット |
| EDINET（金融庁） | 有価証券報告書・半期報告書の MD&A | API キーがある場合 |
| 手入力 | 決算説明会の質疑応答など | 画面のフォーム、またはファイル配置 |

TDnet は過去分を公開していないため、稼働開始より前の四半期は取れません。毎日動かし続けることで四半期ごとに積み上がります。無効にするには `RIPPLE_NO_TDNET=1`。

## 「ひとつ買うなら」の選び方

候補（合成スコア上位5%）に「選定スコア上位20」を加えたプールから、決算発表から45営業日以内の銘柄を対象に、次の選定スコアが最も高い1銘柄を選びます。

```
土台     = 過去データで同じ条件（サプライズ十分位 × 値動きの大きさ三分位）だった決算の平均CAR60
           （件数 100 未満なら十分位全体 → サプライズ三分位 の順に粗くする）
語り口   = 語り口三分位のセルが n ≥ 20 かつ |t| ≥ 1.5 のときだけ、行平均との差分を n/(n+100) で縮小して上乗せ
残り期待 = (土台 + 語り口) × (60 − 経過営業日) / 60
選定スコア = 残り期待 × 減点（保有中に決算 ×0.85、売買代金3億円/日未満 ×0.9）
```

値動きで条件づけるのは、決算後ドリフトが裁定リスク（ボラティリティ）の高い銘柄に集中するという実証（Mendenhall 2004）を、このアプリの過去データでも確認できたためです（例: サプライズ上位10%×値動き大は平均 +2%前後、値動き小はほぼゼロ以下）。カードには土台の件数・t値・勝率、語り口の扱い、想定変動（±）、次点5銘柄との比較表、判定、損切り目安、見直し日、次の決算日が出ます。期待ドリフトが +0.3% 未満なら判定は「見送り推奨」です。過去の平均に基づく目安であり、個別銘柄の予測ではありません。

## 画面の読みかた

| リング | 意味 | 元になる論文 |
|---|---|---|
| ① 決算サプライズ | 利益が事前の予想をどれだけ上回ったか（同時期の銘柄の中での順位）。良い驚きの後は株価がじわじわ上がりやすい（PEAD） | Bernard & Thomas (1989), Meursault et al. (2023) |
| ② 経営陣の自信 | 決算説明の「言葉」を点数化。前向きで言い切りが多いほど高得点 | Meursault, Liang, Routledge & Scanlon (2023) *PEAD.txt* |
| ③ 取引先の追い風 | 大口の取引先の株価が先に上がり、この銘柄がまだ追いついていない度合い | Cohen & Frazzini (2008) *Economic Links and Predictable Returns* |

3 つを合計した「合成スコア」の上位 5%（最低 5 銘柄）が候補です。70 点以上のリングを「点灯」と呼び、3 つとも点灯した銘柄は研究上もっともドリフトが出やすい組み合わせです。

行を押すと、平易な理由・注意点・株価チャート・ドリフトの進み具合・取引先との比較・保有期間の目安が開きます。

## ダークモード

OS の設定（ライト／ダーク）に自動で追従します。ヘッダー右上の丸いボタンで「システム設定に従う → ライト → ダーク」を順に切り替えられ、選択はブラウザに保存されます。チャートやサプライチェーン図の色もテーマに合わせて変わります。

## 「経営陣の自信」を計算するには

決算説明会の質疑応答や、決算短信の「経営成績に関する説明」のテキストを、銘柄の詳細パネルにあるフォームから貼り付けてください。保存すると自動で再計算されます。ファイルで置く場合は `data/transcripts/<証券コード>.T/<発表日 YYYY-MM-DD>.txt`。

英語の書き起こしで FinBERT（`ProsusAI/finbert`）を使いたい場合は `pip install transformers torch` を追加すると自動で有効になります（日本語は同梱の金融極性辞書で採点します）。

## EDINET（有価証券報告書）との連携（任意）

金融庁の EDINET API キー（無料）を `data/edinet_key_fsa.txt` に 1 行で置く、または環境変数 `EDINET_FSA_KEY` に設定すると（`~/cre-scout/tools/edinet_key_fsa.txt` があればそれも自動で使います）、有報の【主要な顧客ごとの情報】から取引先と売上依存度を自動で読み取り、同梱データを実測値で上書きします。また有報・半期報告書の「経営者による分析（MD&A）」本文を、決算説明テキストの代替として採点します（画面では「有報MD&A」「半期報告書MD&A」と表示されます）。有報の提出は決算発表の1〜2か月後なので、発表直後の判断には説明会テキストの貼り付けが有効です。

キー取得: https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1

## データ源

- 株価・予想 EPS・実績 EPS・決算発表日: Yahoo Finance（`yfinance`）
- 取引先の関係: 同梱の seed データ（出典区分つき: 有報開示 / Apple Supplier List / 業界公知の推定）＋ EDINET
- ベンチマーク: TOPIX 連動 ETF（1306）。データ品質チェックに落ちた場合は日経平均に自動切替

  models/sue.py          SUE（アナリスト基準・季節ランダムウォーク）
